# tabloda.uz — табло ближайших поездов и самолётов Узбекистана

Статический сайт: данные лежат в JSON, страница их читает. Бэкенда нет,
хостинг — GitHub Pages, домен tabloda.uz.

Два раздела. **Поезда** (`index.html`): 14 городов, оба направления,
раскрытие маршрута по клику, номера платформ. **Самолёты**
(`flights.html`): 14 аэропортов, вылет и прилёт, фактическое время,
терминалы, стойки регистрации и багажные ленты.

Общее для обоих: три языка (узбекский по умолчанию), светлая и тёмная
темы. Выбор языка и темы хранится под ключами `board-lang` и
`board-theme` — общими, чтобы переход между разделами не сбрасывал их.

## Устройство

```
Яндекс.Расписания ──► build_yandex.py ──► seed.json ──► i18n.py ──► sync.py
                            │                              ▲            │
                            ▼                              │            ▼
                      .cache/threads ──► routes.py     extra.json   schedule.json
                                              │        brands.json       │
                                              ▼                          ▼
                                        routes.json ────────────► index.html
tm.md.uz ──────────► live.py ─────────► live.json ──────────────────────┘

uzairports.com ────► live_flights.py ──► flights_live.json ──► flights.html
                                                    ▲
                                       cities.json, statuses.json
```

Расписание поездов пересобирается раз в неделю, живое табло станций —
раз в час (7-я минута), табло аэропортов — раз в час (27-я минута,
разнесено, чтобы не толкаться за ту же группу `data-write`). Посетитель
скачивает готовые JSON, к сторонним API со страницы не уходит ни одного
запроса.

## Источники и как их искали

### Поезда

**Яндекс.Расписания** — основной. Ключ бесплатный, по заявке. Станции
задаются кодами системы express (те же, что у УТЙ: Ташкент-Центральный
2900001, Южный 2900002, Самарканд 2900700). Эндпоинт `/thread/` отдаёт
маршрут целиком со всеми остановками — благодаря ему страна собирается
из двух станций-якорей.

**tm.md.uz** — живые табло станций, открытый доступ без авторизации.
Даёт платформы, конкретные даты, наличие мест. Семь известных адресов:

    tashkent-central  proxyS.php        urgench   proxyU.php
    tashkent-south    proxyYu.php       bukhara   proxyB.php
    samarkand         proxy.php         qarshi    proxyKarshi.php
                                        andijan   proxyAndijon.php

Имена непоследовательные (ранние — короткие коды, поздние — полные
названия), вычислить нельзя, только подсмотреть в DevTools.

**eticket.railway.uz** — Angular, данных в HTML нет, запросов к своему
API при загрузке не видно, «Скачать расписание» за авторизацией. Отсюда
брали бренды поездов вручную.

**uzrailpass.uz/ru/pages/poezd-jadvali** — единственная страница с
расписанием в обычном HTML. Но данные устарели: 710Ф там 8:40, а по
трём другим источникам 8:37. Не используем.

### Самолёты

**uzairports.com** — единственный источник, авторизации нет. Один
маршрут на все аэропорты и оба направления:

    /flights/{event}?status={event}&airport={IATA}

JSON-эндпоинта нет, страница рендерится Laravel'ом на сервере, но
разметка семантическая (`flight-result__content`, `flight-code`,
`terminal`), парсится устойчиво. Заголовок `Accept: application/json`
и префиксы `/ru/`, `?lang=ru` игнорируются — отдаётся всегда узбекский.

Четырнадцать аэропортов: TAS, SKD, BHK, UGC, NMA, AZN, FEG, KSQ, NCU,
TMJ, NVI плюс вертолётные площадки Silk Avia RBZ (Шахрисабз), OMN
(Зомин), IYO (Сариасия). Код AFS (Зарафшан) отвечает пустой страницей.

**Яндекс.Расписания для самолётов** — проверен и отвергнут. Отдаёт
плановую сетку и тип борта, которых нет на табло, но не знает части
внутренних рейсов Silk Avia (UH704, UH722, UH756, UH758, UH762) и
аэропорта Сариасия, а дни курсирования отдаёт текстом с сезонной
границей («вс по 18.10»). Разведочный скрипт `flights_probe.py`
оставлен на случай, если табло изменит разметку.

## Подводные камни (все проверены на данных)

### Поезда

**Цифры номера не идентифицируют рейс.** Это главная ловушка проекта,
подводила трижды: при сравнении с Яндексом, при расчёте отклонений и при
подстановке маршрутов. 054Ф идёт Ташкент → Кунград, 054Щ обратно; 056Ч и
056Ж — встречные. Суффиксы плавают между источниками (латиница у Яндекса,
кириллица на табло), однозначного соответствия нет. Сшивать можно только
по цифрам **вместе с направлением или временем**.

**Дни курсирования выводятся эмпирически.** Яндекс отдаёт их текстом
(«ежедневно», «кроме 3 сентября»), разбирать ненадёжно. Опрашиваем
расписание на 14 дней: каждый день недели попадает дважды, разовые
пропуски видно. При семи днях любая дырка давала неверный шаблон.

**Чётные и нечётные числа шаблоном не описываются.** 071Ф и 072Ф на Алат
ходят по числам месяца, а не по дням недели, и всегда светятся в списке
«дни под вопросом». Чинится только хранением конкретных дат.

**Сдвиг суток берётся из дат ответа**, а не выводится из порядка времён.
Так корректно считаются и переход через полночь, и рейсы длиннее суток.

**Бренд по номеру не угадывается.** Первая версия считала все 7xxF за
Афросиёб — неверно: 710Ф это Sharq, 716Ф Nasaf, 730Ф O'zbekiston.
Хранится в `brands.json`, перепроверено по разделу «АФРОСИЁБ» на
uzrailpass.

**Порядок команд важен.** `i18n.py` и `sync.py` работают с тем, что лежит
в `seed.json` на момент запуска. Прогон до сборки пересоберёт старый
набор, и будет казаться, что сборка не сработала.

**`rm schedule.db` перед `sync.py --seed`** обязателен, иначе новые поля
в базу не попадут: скрипт увидит те же записи и напишет «0 добавлено».

### Самолёты

**Сотня — это лимит, а не количество.** У Яндекса `limit=100` по
умолчанию; при 110 рейсах десять невидимы. Та же ошибка, что с 485
записями поверх 574. `fetch_schedule` ходит постранично и при неполной
выдаче отказывается писать.

**Имя перевозчика в источнике бывает неверным.** Яндекс резолвит код UH
в «Uzbekistan Helicopters», хотя это Silk Avia — внутренние рейсы на
Бухару, Термез, Карши, Самарканд, Андижан, Фергану. Едва не отфильтровали
как вертолётные. Тот же класс ошибки, что с брендами 7xxF.

**Табло отдаёт трое суток сразу**, причём дальние дни неполны
(29.08 — 81 запись, 30.08 — 112, 31.08 — 45). Дублей нет, фильтровать
надо по `date`.

**Поле `check-in` значит разное по направлениям**: у прилёта это
багажная лента, у вылета — стойки регистрации. Подпись встроена в
значение (`Yuk Karusel 02`), поэтому берём только вложенный `<span>`,
а подпись подставляем свою.

**Статусы приходят строкой на узбекском**, но их конечное число: пять
фиксированных и два шаблона с подстановкой времени. Приводятся к коду в
`normalize_status`, переводятся через `statuses.json`. Отдельно
обрабатывается `xx:xx gacha kechiktirildi` — задержка без известного
времени.

**HTML-сущности надо декодировать.** `Farg&#039;ona` в разметке —
норма, `clean()` прогоняет через `html.unescape`.

**Горизонт разный по направлениям.** На вылет приезжают заранее, поэтому
5 часов; встречающему хватает 3. Улетевший рейс убирается сразу,
прилетевший висит ещё полчаса — полезно видеть, что борт сел.

## Чего нет

**Фактических задержек у поездов.** Все четыре железнодорожных источника
отдают плановое время. `live.py` умеет сравнивать табло с расписанием и
копит историю отклонений; постоянная величина означает расхождение в
данных, плавающая — настоящую задержку. Различить можно только
наблюдением за несколько дней. По состоянию на конец августа 2026 вывод
не сделан. У самолётов фактическое время есть прямо в источнике.

**733Ф и 734Ф у Яндекса отсутствуют**, хотя на сайте УТЙ есть и билеты
продаются. Добавлены вручную через `extra.json`, который подмешивается
после каждой сборки.

**Типа борта у самолётов.** Есть только у Яндекса (в 83% случаев), на
табло нет. Единственная причина, по которой к нему стоило бы вернуться.

**Дней курсирования у самолётов.** Табло знает трое суток вперёд, и
этого достаточно при суточном горизонте планирования.

**Пригородных электричек** — их больше и график меняется чаще.

**Мест и цен** — есть в источниках, устаревают за минуты.

## Команды

Расписание поездов, при смене графика (дважды в год):

```bash
export YANDEX_RASP_KEY=...
python3 build_yandex.py --apply     # ~5 минут, 69 маршрутов
python3 i18n.py                     # города, переводы, бренды, extra.json
rm schedule.db
python3 sync.py --seed
python3 routes.py                   # маршруты из .cache/threads
```

Живые табло, часто (обычно через Actions, вручную — для проверки):

```bash
python3 live.py                     # станции: платформы, отклонения
python3 live.py --history           # разброс отклонений за всё время
python3 live_flights.py             # аэропорты, ~700 записей за трое суток
python3 live_flights.py --airport TAS --event departure
python3 live_flights.py --file /tmp/tas.html --airport TAS  # разбор без сети
```

Разведка:

```bash
python3 yandex.py --probe                 # проверить ключ и коды станций
python3 yandex.py --route samarkand       # маршрут рейса с кодами остановок
python3 build_yandex.py --inventory       # все станции, что встретились
python3 compare.py                        # сравнить два набора данных
python3 flights_probe.py --airports       # коды аэропортов у Яндекса
python3 flights_probe.py --fields s9600397 --date 2026-08-30
```

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | раздел поездов целиком: стили, логика, три языка, темы |
| `flights.html` | раздел самолётов, то же оформление |
| `build_yandex.py` | сборка расписания поездов через маршруты рейсов |
| `yandex.py` | клиент API: повторы при 429, кэш маршрутов |
| `routes.py` | маршруты для раскрытия, все варианты направлений |
| `live.py` | табло станций: платформы, даты, отклонения |
| `live_flights.py` | табло аэропортов: статусы, терминалы, факт |
| `flights_probe.py` | разведка авиаданных у Яндекса, запасной путь |
| `i18n.py` | города, переводы, бренды, подмешивание extra.json |
| `sync.py` | база, сверка, экспорт JSON |
| `brands.json` | бренды поездов по цифрам номера |
| `extra.json` | поезда, которых нет у Яндекса |
| `cities.json` | направления самолётов по IATA, три языка |
| `statuses.json` | статусы рейсов по коду, три языка |
| `stations.json` | коды станций из бандла сайта УТЙ |
| `assets/` | логотип, иконки, картинка для шеринга |

Скрипты ручной сборки — `from_table.py`, `build_station.py`,
`parse_direction.py` — оставлены как запасной путь, если ключ отзовут.
Они собирают данные из текста, скопированного со страниц eticket.

## Обязательства

По условиям API Яндекс.Расписаний на сайте должно стоять указание
источника: «Данные предоставлены сервисом Яндекс Расписания» со ссылкой
на rasp.yandex.ru, шрифтом не меньше основного и тем же цветом. Стоит в
`index.html` над подвалом отдельным блоком — убирать нельзя. Требование
распространяется на все места, где показываются данные Яндекса, включая
будущего телеграм-бота.

**На `flights.html` этой атрибуции нет и быть не должно** — данные
Яндекса там не используются. Вместо неё указан uzairports.com.

## Работа с репозиторием

Работа идёт с двух машин (`sk` и `shkurbanov`). До 29 августа 2026
файлы переносились архивами, что дважды приводило к рассинхрону: в
репозитории оказалась старая версия `from_table.py` с уже исправленной
ошибкой брендов, а локальная копия отставала на неделю. Теперь только
git по SSH.

```bash
git pull            # перед началом работы, обязательно:
                    # Actions коммитит данные каждый час
git add -A && git commit -m "..." && git push
```

При конфликте в генерируемых данных спорить не о чем:

```bash
git checkout --ours data/flights_live.json
git add data/flights_live.json
GIT_EDITOR=true git rebase --continue
```
