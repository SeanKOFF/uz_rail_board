# Табло ближайших поездов — Узбекистан

Статический сайт: расписание лежит в `data/schedule.json`, страница его читает.
Бэкенда нет.

Сейчас в базе пять городов: Ташкент, Бухара, Карши, Ургенч, Андижан.

## Откуда данные

API найти не удалось. Страницы eticket.railway.uz рисует Angular, в исходном
HTML данных нет, запросов к своему бэкенду при загрузке не видно, а кнопка
«Скачать расписание» закрыта авторизацией. Поэтому источник — **текст,
скопированный со страниц сайта**, в двух разных видах:

| Что копируем | Откуда | Что даёт |
| --- | --- | --- |
| Общая таблица | `/ru/pages/schedule` | номера, дни курсирования, начало и конец маршрута |
| Выдача поиска | `/ru/pages/trains-page` | время на промежуточных станциях, бренды, вокзалы |

Две выборки сшиваются по цифрам номера и дополняют друг друга: первая знает
«в какие дни», вторая — «во сколько где».

## Сборка

```bash
# 1. Ташкент — из общей таблицы (обе вкладки: Отправление и Прибытие)
python from_table.py departures.txt --direction departure
python from_table.py arrivals.txt   --direction arrival --merge

# 2. Остальные города — из парных выдач поиска
python build_station.py Бухара bukhara \
    --inbound to_bukhara.txt --outbound from_bukhara.txt --merge

# 3. В базу и в JSON
python sync.py --seed
python -m http.server 8000
```

`--inbound` — выдача «Поезда в <город>», `--outbound` — «Поезда в Ташкент»
со страницы отправления из этого города. Без outbound город получится
однобоким: у Андижана сейчас только прибытия.

Расписание меняется дважды в год, так что процедура нечастая.

## Подводные камни (все проверены на данных)

**Время на станции стабильно, дни — нет.** Сверка двух дат по 15 общим рейсам
дала ноль расхождений во времени. Значит, достаточно одной даты на направление;
дни курсирования берутся из общей таблицы, а не из выдачи поиска.

**Переход через полночь сдвигает день.** Поезд уходит из Ташкента в 22:35 и
проходит Бухару в 06:28 — это уже следующие сутки, дни курсирования сдвигаются
на +1. Без этого табло врёт на день. Реализовано в `shift_days()`.

**Чётные и нечётные числа сдвинуть нельзя.** 072Ф ходит по чётным из Ташкента,
но дальние станции проходит уже по нечётным. Такие рейсы сдвиг не обрабатывает —
на удалённых станциях они будут врать на сутки. Чинится хранением конкретных
дат вместо шаблона.

**У проходящего поезда время одно.** Стоянка длится несколько минут и в
источнике не указана, поэтому транзитный рейс попадает на оба табло с одним
временем и пометкой `through`. Для Самарканда это 29 рейсов из 30, для
Бухары — 8 из 14.

**Суффиксы номеров плавают.** Один поезд встречается как 054Ф, 054Щ, 054;
126Ф, 126Ч, 126. Стабильны только цифры — сшивка идёт по ним, для показа
берётся номер из общей таблицы.

**Названия бывают на трёх языках** и с разными апострофами: `Qo'ng'irot`,
`Qung'irot`, `Кунград`. Нормализуются через `stations.json`.

**Бренд по номеру не угадывается.** Первая версия считала все 7xxF за
Афросиёб — неверно: 710Ф это Sharq, 716Ф — Nasaf, 730Ф — O'zbekiston.
Бренд берётся только из выдачи поиска.

**Не все города на линии.** 054 идёт на Кунград через Нукус, минуя Ургенч —
проверено отдельным запросом. Отсутствие поезда в выдаче не всегда означает
дырку в данных.

## Что не покрыто

- **Фактические задержки.** Только плановое время; в подвале сайта это написано.
  Единственный известный источник факта — табло UzGPS (`smpo.uzgps.uz`), но оно
  отдаёт пустую таблицу и закрыто robots.txt.
- **Пригородные электрички.** Их больше и график меняется чаще.
- **Наличие мест и цены.** В выдаче поиска есть, но устаревают за минуты —
  сознательно не сохраняются.
- **Города с одним-двумя рейсами** (Нукус, Шахрисабз, Сарыасия). Табло из
  одной строки выглядит сломанным.
- **Самарканд** — был собран и потерян при пересборке, нужны свежие вставки.

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | сайт: выбор города, отправление/прибытие, отсчёт до рейса |
| `from_table.py` | общая таблица → seed |
| `parse_direction.py` | разбор выдачи поиска; умеет сверять две даты |
| `build_station.py` | парные выдачи → табло станции |
| `sync.py` | база, сверка с источником, экспорт JSON |
| `stations.json` | 16 направлений с кодами (из бандла сайта) |
| `transit.json` | дни курсирования транзитных рейсов |

Коды станций в `stations.json` — те же express-коды, что принимает API
Яндекс.Расписаний. Если до него дойдёт, меняется только `scrape()` в `sync.py`.

## Планировщик

`.github/workflows/weekly-sync.yml` — понедельник, 09:00 по Ташкенту.
Пока источник не автоматизирован, задача полезна как наблюдение: сверяет
публичную таблицу с базой и сообщает о расхождениях, не применяя их вслепую.
Если источник вернёт меньше половины известных рейсов, прогон прерывается
и база остаётся нетронутой.
